**Окружение:** Node 22, Next.js 16.3.5, PostgreSQL 16.13, Chromium 141 headless,
1440×900 и 390×844. Приложение — production-сборка (`next build` + `next start`),

SQL-запросом к PostgreSQL, а не только текстом страницы.

## Найденный и устранённый дефект

| ID | Дефект | Причина | Исправление | Как проверено |
|---|---|---|---|---|
| **D2-1** | Срок задачи выводился как «Wed Sep 23» вместо «23.09.2026», и **подсветка просроченных не работала вообще** — ни одна просроченная задача не выделялась | драйвер `pg` по умолчанию отдаёт колонку `DATE` как объект JS `Date`; `String(date).slice(0,10)` давал «Wed Sep 23», а сравнение строки с `YYYY-MM-DD` всегда было ложным | `src/lib/db.js` — `types.setTypeParser(1082, v => v)`: DATE приходит строкой; формат вывода и признак просрочки вынесены в `formatDate()` и `isOverdue()` в `src/lib/domain.js`, чтобы правка была в одном месте | проверки 34–36: формат ДД.ММ.ГГГГ, просроченная задача помечена, задача без срока выводится как «без срока»; в демо-данные добавлена заведомо просроченная задача |

Дефект найден не автотестом, а просмотром реального скриншота: тест 33/33 был «зелёным»
и при сломанном выводе даты. Это тот же урок, что и в Кейсе №1 — PASS обязан означать
работающую функцию.

**Дефект тестового стенда (не приложения):** первая кнопка `submit` на странице — это
форма выхода в шапке, поэтому неквалифицированный клик отправлял её вместо формы задачи.
В `e2e/check.js` форма ищется по полю внутри неё (`submitFormWith`). Та же ошибка уже
ломала тесты Кейса №1 — вынесена в комментарий прямо в коде теста.

## Что именно проверено (36 проверок)

**Авторизация (1–4).** Аноним перенаправляется на вход; неверный пароль даёт сообщение
и не пускает; администратор входит; список задач отображается.

**Создание и назначение (5–7).** Задача создаётся с выбранным исполнителем и статусом
«Новая»; модуль определяет категорию «Дизайн» по тексту; задача видна в списке.

**Авто-распределение (8–11).** При включённом авто-распределении исполнитель назначается
модулем (`ai_assigned = true`); категория «Разработка» определена по тексту; слова
срочности подняли приоритет до высокого; исполнитель выбран по специализации.

**Фильтрация (12–15).** Фильтры по категории, статусу и исполнителю и поиск по названию
дают корректную выборку (проверяется и наличие нужной задачи, и отсутствие лишних).

**Статусы и история (16–18).** Смена статуса пишется в БД, переживает перезагрузку,
история изменений пополняется.

**Панель администратора (19–21).** Открывается; администратор создаёт сотрудника;
новый сотрудник входит с выданным паролем.

**Границы прав (22–29).** Сотрудник видит свои задачи и не видит чужие; ссылки на админку
у него нет, по прямой ссылке его разворачивает; выбора исполнителя в форме нет, и задача
создаётся на него самого (проверено в БД); формы смены статуса чужой задачи не выводится,
статус чужой задачи не меняется.

**Выход и валидация (30–33).** Выход возвращает на вход, после выхода задачи недоступны;
задача с названием короче 3 символов не создаётся; несуществующая страница → HTTP 404.

**Даты (34–36).** Формат ДД.ММ.ГГГГ; просроченная задача помечена; «без срока» выводится
для задач без даты.
