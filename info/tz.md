## 1. Что прямо указано в объявлении [ЗАКАЗ]

- Веб-приложение для автоматизации управления задачами, проектами и сотрудниками.
- Регистрация и авторизация пользователей.
- Создание и управление задачами.
- Назначение задач сотрудникам.
- Отображение статуса выполнения.
- Фильтрация задач.
- Панель администратора для управления пользователями.
- Модуль ИИ для автоматической категоризации и распределения задач.
- Стек: Next.js + Tailwind CSS, Node.js (Express/Fastify), PostgreSQL, Supabase Auth,
  OpenAI API; деплой Vercel + Render/Heroku.

## 3. Вопросы клиенту (задал бы до начала работы)

1. Проекты нужны как отдельная сущность или задачи живут плоским списком?
2. Какие статусы задач приняты у вас сейчас и кто имеет право их менять?
3. Что именно должен делать ИИ-модуль: только предлагать категорию и исполнителя
   или назначать автоматически без подтверждения человеком?
4. Чей аккаунт OpenAI и Supabase используется, кто оплачивает токены?
5. Сколько сотрудников в системе и нужен ли импорт существующего списка?

## 4. Цель MVP

Рабочее приложение, в котором администратор заводит сотрудников, ставит задачи,
назначает исполнителей (вручную или автоматически), а сотрудник видит свои задачи
и ведёт их по статусам. Всё — в одном Next.js-приложении с PostgreSQL.

## 5. Роли [ЗАКАЗ: «панель администратора», роли явно не расписаны — состав УРОК]

| Роль | Может |
|---|---|
| **admin** (администратор) | видит все задачи; создаёт задачи и назначает любого исполнителя; включает авто-распределение; заводит, редактирует и отключает сотрудников |
| **employee** (сотрудник) | видит только свои задачи (назначенные ему или поставленные им); создаёт задачи только на себя; меняет статус своих задач; в панель администратора не попадает |

## 6. Экраны

1. `/login` — вход по email и паролю.
2. `/tasks` — список задач: поиск по названию, фильтры (статус, категория, исполнитель),
   смена статуса прямо в карточке, подсветка просроченных.
3. `/tasks/new` — постановка задачи: название, описание, приоритет, срок,
   исполнитель либо авто-распределение.
4. `/admin` — сотрудники: таблица с нагрузкой, добавление, включение/отключение.

## 7. Функции MVP

- Вход/выход, серверные сессии, закрытие страниц от неавторизованных.
- CRUD задач (создание и изменение статуса; удаление в MVP не требуется).
- Назначение исполнителя вручную.
- Авто-категоризация по тексту задачи и авто-распределение на наименее загруженного
  сотрудника подходящей специализации.
- Фильтрация: статус, категория, исполнитель, поиск по названию.
- Срок задачи необязателен; просроченные подсвечиваются.
- История изменений задачи.
- Панель администратора: список сотрудников, создание, отключение.

## 8. Отклонения от стека заказа (осознанные, для учебного MVP) [УРОК]

| Требование заказа | Что сделано | Почему |
|---|---|---|
| Node.js + Express/Fastify отдельным сервисом | Route Handlers и Server Actions самого Next.js | для MVP отдельный бэкенд-сервис избыточен; при росте выносится без переписывания схемы БД |
| Supabase Auth | собственные сессии в PostgreSQL + httpOnly-cookie | Supabase требует аккаунт и ключи клиента; вся логика изолирована в `src/lib/auth.js`, замена затрагивает один файл |
| OpenAI API | детерминированный офлайн-классификатор по словарю ключевых слов | ключ OpenAI платный и принадлежит клиенту; точка замены — функция `categorize()` в `src/lib/ai.js`. **Это не нейросеть**, и так прямо написано в интерфейсе |
| Деплой Vercel + Render | локальный запуск | публикация требует аккаунтов клиента |

PostgreSQL и Next.js + Tailwind CSS — как в заказе, без замен.

## 9. Данные

`users` (роль, должность, специализация, активность), `sessions`, `tasks`
(статус, приоритет, категория, объяснение решения модуля, исполнитель, постановщик, срок),
`task_history`. Схема — `db/schema.sql`.

## 10. Критерии приёмки MVP

1. Неавторизованный пользователь не попадает ни на одну страницу, кроме входа.
2. Неверный пароль → понятное сообщение, вход не происходит.
3. Администратор создаёт задачу и назначает исполнителя из списка сотрудников.
4. Модуль определяет категорию по тексту задачи.
5. Авто-распределение выбирает исполнителя по специализации и наименьшей загрузке.
6. Фильтры (статус, категория, исполнитель) и поиск дают корректную выборку.
7. Смена статуса сохраняется в БД и переживает перезагрузку.
8. Администратор заводит сотрудника, и тот входит с выданным паролем.
9. Сотрудник не видит чужих задач и не попадает в панель администратора.
10. Сотрудник не может назначить задачу другому — только на себя.
11. Срок выводится как ДД.ММ.ГГГГ; просроченная задача помечена; задача без срока допустима.
12. Валидация: слишком короткое название не проходит; несуществующая страница → 404.
